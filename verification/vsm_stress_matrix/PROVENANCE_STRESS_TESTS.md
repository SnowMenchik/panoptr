# Протокол и верифицированные артефакты стресс-матрицы ВСМ (0–400 км/ч)

Данная папка содержит машиночитаемые отчёты (`JSON` и `CSV`) двух взаимодополняющих серий контрольных испытаний программного комплекса **PANOPTR**:

1. **Прогон с эталонной GT-разметкой и компенсацией вибрации (`gt_verified_runs` в `stress_matrix_summary.json` и `stress_matrix_summary.csv`)** — воспроизводится одной командой:
   ```bat
   09_Прогон_стресс_матрицы_ВСМ.bat
   ```
   или напрямую через Python:
   ```bash
   python 02_Реализация/panoptr/run_vsm_stress_matrix.py
   ```
   В этом прогоне 260 кадров коридора пути (25 FPS, 156 эталонных аномалий в `ground_truth_stress_matrix.json`) проходят через конвейер `vsm_simulator/effects.py` (`apply_effects`, `vibration_matrix`, `transform_boxes`) и `vsm_simulator/metrics.py` (`match_frame` при `IoU >= 0.5`). Для каждого из 5 сценариев вычисляются `TP`, `FP`, `FN`, `Precision`, `Recall`, `F1`, `p95_latency_ms`, `camera_recovery_sec` и `gnss_recovery_sec`.

2. **Прогон боевой модели YOLO26 на натурном видеопотоке на GPU стенда (`hardware_gpu_field_video_runs` в `stress_matrix_summary.json`, подробно описан в `03_Протокол_контрольных_испытаний_PANOPTR_ВСМ.pdf`)**:
   - Измеряет реальную задержку инференса YOLO26 + наложения эффектов ВСМ на физическом GPU (`средняя задержка 62,63–65,87 мс`, `P95 = 70,95–80,82 мс`, `FPS = 11,42–13,75`, восстановление после 3-секундного отключения камеры за `0,015–0,040 с` и после 4-секундной потери GNSS за `0,020–0,030 с`).
   - Поскольку исходный полевой видеоролик не имел покадровой разметки `ground_truth.json`, симулятор `vsm_simulator/runner.py` в соответствии со своей спецификацией (`README_RU.md`) честно вывел `N/A` в полях `missed_known_defects` и `false_alarms`, не фабрикуя фиктивный эталон по собственным предсказаниям модели.
