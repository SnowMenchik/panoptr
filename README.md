# PANOPTR

Прототип системы компьютерного зрения для видеоконтроля железнодорожной инфраструктуры. Результаты предназначены для проверки специалистом; приложение не управляет поездом.

## Установка с чистого скачивания: Windows 10/11 x64

1. Python и команда `py` не требуются: установщик скачает проверенный Python 3.12 x64 отдельно в папку проекта. Нужны Windows x64 и интернет.
2. Скачайте ветку проекта целиком, распакуйте в доступную для записи папку. Не запускайте файлы внутри архива.
3. Запустите `00_Установить_среду.bat`. Нужен интернет: установщик создаёт новое изолированное окружение в `data/envs` и устанавливает зависимости, включая `opencv-python` (`cv2`). Он не удаляет папки в системном Python и не использует старый `runtime`.
4. Запустите `00_Скачать_модели.bat` (интернет, около 300 МБ). Скрипт скачивает 19 основных весов из зафиксированного коммита и проверяет размеры и Git blob hash. Существующие файлы он не перезаписывает. Если файл повреждён, сохраните его отдельно и повторите загрузку.
5. Запустите `05_Проверить_сборку.bat`, затем `01_Запустить_CPU.bat`. Выберите видео или камеры и запустите каналы в окне. Состояние проверки — `data/last_check.json`.

**Если cv2 перестал импортироваться:** закройте приложение и снова запустите `00_Установить_среду.bat`. Установщик скачает отдельный Python и создаст новую среду; старые файлы и системные библиотеки не удаляются. Переключение произойдёт только после успешной проверки импортов. Для установки требуется свободное место и интернет. GPU-версия PyTorch и совместимый драйвер NVIDIA настраиваются отдельно; стандартная установка не гарантирует CUDA.

## Другие команды

- `02_Запустить_GPU.bat` — запуск с выбором GPU; наличие CUDA проверяется отдельно.
- `03_Лаборатория_данных.bat`, `04_Карта_рейсов.bat`, `06_Полигон_и_финал.bat` — дополнительные модули.
- `07_Тесты_после_доработок.bat` — автоматические тесты; `08_Диагностика_камер.bat` — проверка камер; `09_Прогон_стресс_матрицы_ВСМ.bat` — программные сценарии.

Ветка не содержит полноценного портативного Python, всех обучающих данных и дополнительных весов авторазметки. Некоторые видео в старой сборке являются указателями Git LFS: скачайте исходники через Git LFS либо выберите собственное видео. `02_Реализация/panoptr/finale_examples/rail_fallback.avi` — отдельный пример рельсового видео, не видео с БПЛА. Программа не подменяет пользовательские видеофайлы.

Проверка импорта и моделирование не подтверждают натурную работу на ВСМ, качество обнаружения, совместимость с промышленными камерами или работу на другом компьютере. Нужны отдельные испытания. Технические ограничения и лицензии компонентов сохраняются в документации проекта.

## Работа оператора: что изменено в интерфейсе

- **Цвет решения в журнале событий.** Строка таблицы окрашивается по решению оператора, текст решения остаётся в столбце «Решение оператора»: зелёный — подтверждено, красный — отклонено, серый — закрыто без решения, жёлтый — ещё не проверено. Наблюдение модели («Кандидат», «Повторные», «Плохие данные») показывается отдельно и цветом не маскируется.
- **«Закрыть без решения»** — это пропуск, а не подтверждение и не отклонение: карточку посмотрели, но по снимку нельзя ни подтвердить событие, ни назвать его ложным. В сводке такие события не считаются подтверждёнными.
- **Комментарии оператора.** Комментарий сохраняется вместе с решением и виден в столбце «Комментарий». После нажатия кнопки решения поле очищается; последние восемь комментариев доступны стрелками ↑ и ↓ в поле и хранятся в `data/ui_state/operator_notes.json`.
- **Столбцы «Зона» и «Снимок».** В окне есть кнопка «Что означают столбцы» с расшифровкой: «Не задана» — зона не настроена, «Контактная сеть» и «Воздушное наблюдение» — наземная зона к этим классам не применяется; «Снимок: Есть/Нет» — сохранён ли кадр-доказательство.
- **Экспорт.** Кнопка называется «Экспорт ZIP (CSV + JSON + PNG)»: в ZIP всегда `events.csv`, `events.json`, `summary.json`, `telemetry.json` и папка `evidence` со снимками и клипами. Отдельного выбора «только CSV» нет; после экспорта выводится состав архива и его размер.
- **«Готовность».** Та же проверка, что и `05_Проверить_сборку.bat`, но результат разбирается словами: итог, Python, библиотеки, дочерний процесс, CUDA, веса каналов, ошибки и путь к `data/last_check.json`. Кнопка «Открыть папку data» показывает, где лежит результат.
- **«Полигон и финал».** На вкладке «1. Сквозной показ» добавлен кадр из того же канала: это второй пульт к каналам главного окна, отдельная камера не открывается. На вкладке «2. Серия испытаний» статусы опытов различаются цветом («идёт», «завершён, ждёт оценки», «проверен», «прерван»), а кнопки включаются только тогда, когда действие возможно, поэтому «Завершить опыт» больше не предлагается для уже завершённого опыта. Если карточек нет или не указано обоснование, выводится конкретное объяснение.
- **«Карта рейсов».** Строки окрашены по статусу проверки. Если подключённый журнал не дал ни одного объекта с проверенным местом, карта прямо сообщает об этом и предлагает вкладку «Без места»; сообщение о подключении журнала показывает, сколько наблюдений принято и сколько из них без координат.
- **«Лаборатория данных».** Репетиция выполняется одной кнопкой «Создать репетицию», после чего есть отдельные кнопки «Проверить корректный набор репетиции» (ожидается 0 ошибок) и «Проверить набор с ошибками» (ожидаются намеренные замечания по маске, размеру, классу и дубликату).

Цвет и текст интерфейса не заменяют испытаний: решения оператора хранятся отдельно от вывода модели, а Recall и FP/мин без независимого GT не вычисляются.
